## 2025-02-12 - Prevent Information Disclosure and Clickjacking via HTTP Security Headers
**Vulnerability:** Overly permissive HTTP response headers and Express fingerprinting, which can disclose information about the server engine (via `X-Powered-By`), allow MIME-type sniffing, permit unauthorized frame embedding (clickjacking), and allow malicious script injection (XSS).
**Learning:** Standard Express configurations serve assets with a permissive posture, exposing stack traces in non-production environments and omitting security-hardening headers. For an embedded HMI, establishing defense in depth via CSP, X-Frame-Options, X-Content-Type-Options, and X-XSS-Protection mitigates risk without introducing additional external library overhead.
**Prevention:** Ensure all Express-based HMI backend applications disable server fingerprinting headers and configure a strict custom Content Security Policy that supports only required local assets and trusted CDNs (e.g. Google Fonts and Lucide).
