## 2026-08-06 - Strict Custom Security Response Headers and Information Disclosure Hardening
**Vulnerability:** Missing custom HTTP response security headers (CSP, X-Frame-Options, X-Content-Type-Options, etc.) and leakage of the `X-Powered-By: Express` header, leaving the HMI backend susceptible to clickjacking, MIME-sniffing, XSS, and tech stack scanning.
**Learning:** In customized embedded/HMI environments (like the Shiv Kaushalya EAV-700), standard third-party defense suites (like Helmet) are often avoided to prevent bloating node_modules. A customized, strict Content Security Policy (CSP) is required to allow inline assets ('unsafe-inline') and trusted CDN dependencies (unpkg.com for Lucide icons, fonts.googleapis.com, and fonts.gstatic.com for Google Fonts) while restricting unauthorized origins.
**Prevention:** Explicitly disable Express default signatures using `app.disable("x-powered-by")` and enforce an integrated security headers middleware on the root application router. Ensure CSP policies strictly map only to verified CDN services.
