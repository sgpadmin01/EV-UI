## 2026-08-07 - Framework-less HMI Rendering Optimization via DOM-Write Cache Guards
**Learning:** In a pure vanilla JS front-end lacking a reactive virtual DOM engine, high-frequency animation loops (like `requestAnimationFrame` at 60Hz/120Hz) or frequent interval updates (like 1-second clock and telemetry ticks) can easily bottleneck performance if they write to the DOM (`textContent`, `style.width`) on every execution. Even when the computed numeric value has not changed, updating these properties directly on the DOM element triggers unnecessary DOM tree modifications, style computations, and potentially costly layout paint/reflow cycles.
**Action:** Always implement local, simple cache guards ("dirty checking") prior to mutating DOM text or style properties in high-frequency loops or interval callbacks. Only perform the DOM write if the newly formatted value differs from the previously recorded state. This micro-optimization completely eliminates redundant layout/paint cycles, keeping the CPU cooler and the HMI interface incredibly snappy.
