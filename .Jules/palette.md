## 2026-03-01 - Focus Mapping for Custom Touch Controls & ARIA Tab Semantics in Frameworkless HMIs
**Learning:** In highly customized, frameworkless touchscreen interfaces, native accessibility outlines are often lost. Specifically, when inputs like checkboxes are hidden to style custom toggle switches (`.hmi-toggle`), keyboard tab focus becomes completely invisible to the user. Similarly, custom CSS range sliders (`.hmi-slider`) lack high-contrast focus rings unless explicitly styled via `:focus-visible`. Additionally, screen readers cannot interpret dynamic single-page HMI tabs unless explicit WAI-ARIA tab semantics (`role="tablist"`, `role="tab"`, `role="tabpanel"`, and `aria-selected` toggles) are implemented and handled via state transitions in JavaScript.
**Action:** Always map focus indicator styles to the visible custom elements using sibling selectors (e.g., `.hmi-toggle input:focus-visible + .hmi-toggle-slider`). For single-page dashboard tab views, pair semantic markup with JavaScript-driven ARIA state-switching during view transitions.
