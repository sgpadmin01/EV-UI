## 2026-08-13 - Missing Custom Security Headers and Express Information Disclosure
**Vulnerability:** The Express backend lacked security headers (such as Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy) and leaked its technology stack via the default 'X-Powered-By: Express' header. This left the fixed-frame touchscreen HMI vulnerable to clickjacking, MIME-sniffing, and potential script injection while leaking implementation details.
**Learning:** Default Express installations have permissive headers and leak technology details. While security packages (like Helmet) are useful, a lightweight, custom security headers middleware tailored to allow necessary offline and online assets (like Lucide icons via unpkg.com and Google Fonts via Google APIs/Gstatic) is often more precise for low-dependency embedded/SBC environments.
**Prevention:** Always disable the 'X-Powered-By' header on app initialization and implement standard defensive HTTP response headers within a dedicated, explicit security middleware designed to fit the specific external asset integration constraints of the application.
